## 1. 审计目的

验证系统不是“页面可用、接口空转”的演示壳：

1. 独立 SPA 必须通过 Vite 代理调用真实 Spring Boot API，并由 JWT 取得业务数据。
2. 六个角色工作台的主要只读端点必须返回 `code=0` 且有真实数据库数据支撑。
3. 统计、审计、收费单详情和队列看板必须使用正确的 `datetime` 参数与归属规则。
4. 患者不得读取他人收费单、就诊、处方或队列身份；医生不得读取/确认他人队列或统计他人工作量。
5. WebSocket 不得把员工完整看板广播给患者。

## 2. 审计脚本与运行方式

```bash
cd frontend
npm run check:connectivity
```

脚本：`scripts/read-only-connectivity-audit.mjs`。

报告：`docs/images/read-only-connectivity-report.json`。

脚本会登录 `pt0001`、`pt0002`、`pt0004`、`nurse01`、`zhangming`、`lihui`、`cashier01`、`pharma01`、`pharma02`、`admin01`，分别从直接 API 和 Vite 代理发起请求，并用 MySQL 客户端只读核对演示单据归属。除登录外不创建、不修改业务数据；脚本只写验收报告 JSON。

## 4. 发现的问题与修复

| 级别 | 问题 | 修复 |
| --- | --- | --- |
| P0 | `GET /api/bills/{billId}` 只做角色授权，`pt0002` 可读取患者 1 的收费单、金额和明细 | `BillingController.detail` 注入 `AuthUser`，`BillService.detail(billId, user)` 在 PATIENT 角色下核对 `bill.patientId == user.refId`，非本人返回 `code=403` |
| P1 | `GET /api/queue/board` 对 PATIENT 返回全量患者姓名、病历号和患者 ID | `QueueService.board(...)` 要求患者存在同医生、同日期的有效挂号；返回时仅保留本人 `patientId/patientNo/patientName`，其他候诊者三项置空 |
| P1 | 医生可读取其他医生的队列，并可确认其他医生队列的到诊 | 医生看板与到诊确认均核对 JWT `refId` 与挂号单 `doctorId`，不一致返回 `code=403` |
| P1 | 医生工作量统计返回全院医生数据 | `StatsService.workload(...)` 在 DOCTOR 角色下只保留本人就诊，管理员仍返回全院聚合 |
| P1 | WebSocket 原先向同一个 `/topic/queue/{doctorId}` 广播完整患者身份 | V1.6 先新增 `QueueEventPublisher`：员工订阅 `/topic/queue/{doctorId}/{workDate}` 接收完整看板；当时患者共享 `/topic/queue/{doctorId}/{workDate}/masked` 接收脱敏看板。V1.7 再按运行态审查改为患者专属 `/masked/{patientId}`，由 `WebSocketAuthInterceptor` 校验本人归属并拒绝员工完整主题 |
| P1 | 队列归属存在性查询缺少日期条件，可能跨日期授权 | `RegistrationRepository.existsPatientInDoctorQueue` 增加 `schedule.workDate = :workDate` |

患者端界面同步调整：当前叫号为其他患者时显示「其他患者（已脱敏）」，不再渲染空姓名或他人身份。

## 6. 验收结论与边界

2026-11-06 实际执行结果：

- Maven `clean package`：PASS。
- Vite `npm run build`：PASS。
- `npm run check:connectivity`：PASS，`findings=[]`、`errors=[]`、`passed=true`。
- `npm run check:ui`：PASS，患者和护士均显示「实时队列已连接」，无 JS exception / error-warning 日志。
- `UI_BASE=http://127.0.0.1:5174 npm run check:dynamic`：PASS，医保失败生成唯一 FAILED 流水并保持 RETRY，390px 六工作台无溢出。
- `npm run check:ws`：PASS，患者专属主题、员工完整主题授权、订阅拒绝与广播 payload 脱敏均通过，临时夹具零残留。
- `npm run check:audit`：PASS，挂号、报到、到诊、划价、定时过号均记录操作人/SYSTEM、动作、目标 ID；审计切面在业务事务释放连接后以 `REQUIRES_NEW` 落库。
- `npm run check:perf`：PASS，3 轮 50 并发共 150 次成功，单轮 P95 705/549/525ms，汇总 P95 642ms，夹具零残留。
- `npm run check:docs`：PASS，文档、机器报告、图集索引、脚本与独立 SPA 基线一致。

边界：

1. 本审计覆盖主要业务连通性和典型归属边界，不是全部 REST 端点的渗透测试清单。
2. WebSocket 连接状态有 UI 证据；V1.7 起主题订阅授权、广播 payload 与订阅级脱敏由 `npm run check:ws` 单独验收，UI 的「实时队列已连接」不再表述为安全验收。断线后 15 秒轮询的浏览器交互实测仍未单独形成脚本。
3. 未覆盖 10 万数据量、收费接口压测、真实广域网 RTT、生产容量规划、断线轮询交互与全量端点 × 角色 × 对象归属矩阵。
4. 医保仍为 `MockInsuranceGateway`，NORMAL/FAIL/TIMEOUT 只验证可替换接口和失败重试语义，不代表医保局联调成功。
