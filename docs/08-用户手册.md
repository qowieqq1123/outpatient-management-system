## 1. 快速开始

1. 准备 JDK 21、Node.js 20+、MySQL 8/9，执行 `sql/mysql/01_schema.sql` 与 `sql/mysql/02_data.sql` 初始化 `outpatient` 库。
2. 在项目根目录启动后端：`mvn spring-boot:run`，服务地址为 `http://127.0.0.1:8080`；后端根路径返回 JSON，不提供业务页面。
3. 在 `frontend/` 启动独立 SPA：`npm install && npm run dev`，浏览器打开 `http://127.0.0.1:5173`。
4. 选择登录身份卡片后填写演示账号，口令统一为 `123456`；服务端按账号真实角色签发 JWT，身份卡片只用于预填演示账号。
5. 演示结束点击右上角「退出」，浏览器会清除本地 JWT；也可关闭本机服务。

生产构建执行 `npm run build`，产物位于 `frontend/dist/`；`npm run preview` 默认在 `4173` 预览。生产同源部署见 `docs/07-前后端分离架构与部署说明.md` 与 `deploy/nginx.conf.example`。

## 3. 一次完整就诊演示

推荐按下列顺序操作，能让挂号、分诊、接诊、收费、发药与审计形成闭环：

1. **患者挂号**：用 `pt0001` 登录，在「预约挂号」按日期/科室/医生筛选，选择余量大于 0 且状态为「开放」的排班，点击「立即挂号」。成功后在「我的挂号」查看号序；重复点击同一号源会被服务端拒绝。
2. **患者取消**：对尚未报到、状态为「已挂号」的本人挂号单点击「取消挂号」；号源余量回补，状态变为「已取消」，不生成退费记录。
3. **护士分诊**：用 `nurse01` 登录，在「分诊报到」输入挂号单 ID，或在挂号列表点击「报到」。看板通过 WebSocket 实时刷新；断线时自动轮询 `/api/queue/board`。患者端只显示自己的姓名和病历号，其他候诊者仅显示队列进度。
4. **医生接诊**：用 `zhangming` 登录，在候诊队列叫下一号并确认到诊，开始接诊后书写主诉、诊断、医嘱；可继续开处方和检查单。完成后点击「结束就诊」。
5. **收费员划价**：用 `cashier01` 登录，选择就诊生成/查看收费单，按自费或医保确认收款；医保失败时单据保留「待重试」，可点击「重新结算」。
6. **收费员退号**：对就诊前且可退的挂号单办理退号，系统写入挂号费退费记录、回补号源并留下审计；已就诊或终态重复操作会被中文拒绝。
7. **药房处理**：用 `pharma01` 登录后审核普通处方、发药；精神类处方先审核，再换 `pharma02` 完成第二签字，最后回到 `pharma01` 发药。已发药处方可办理退药。
8. **患者查看结果**：回到 `pt0001` 查看就诊记录、处方/检查明细与账单金额，确认医保失败时不会显示「已收费」。
9. **管理员复核**：用 `admin01` 查看医生工作量、收入、审计日志，必要时手动执行过号扫描。

## 4. 管理员维护

管理员导航新增「账号与角色」「排班维护」两个入口，所有写操作均由 `/api/admin/**` 的 ADMIN 专属 REST 与 Spring Boot 事务校验。

### 4.1 角色

在「角色编码 / 角色名称 / 权限清单」表单新建角色；点击列表中的「编辑」可修改名称与权限清单，编码在编辑态只读。系统不提供角色删除，避免外键引用与历史审计被破坏。权限清单使用逗号分隔，例如 `log:query,user:query`。

### 4.2 登录账号

填写登录账号、姓名、角色、业务档案编号、账号状态与初始口令即可新建账号。患者/医生角色必须填写有效的患者/医生档案编号，其余角色可留空。编辑态可修改姓名、角色、档案关联、启用状态和重置口令；口令留空表示不修改。列表提供「启用/禁用」快捷操作，禁用后该账号无法登录，但不会物理删除。当前登录管理员不能禁用自己或改成非管理员角色。

新建或重置的口令只写入 PBKDF2 哈希；`/api/admin/users` 的返回视图不含 `password_hash`。建议验收时用新账号重新登录一次，确认口令可用。

### 4.3 排班

在「排班维护」选择医生与所属科室，填写未来出诊日期、时段、号源总量和挂号费即可新建。创建时余量等于总量；编辑总量时服务端按 `已占用量 = 总量 - 余量` 计算新余量，禁止把总量调低到已占用量以下。已有挂号占用时不能再更换医生、科室、日期或时段，避免历史挂号单与号源错配。

「停诊」只把状态从「开放」改为「已停诊」，保留已有挂号单；停诊后患者继续挂号会被拒绝，编辑与重复停诊也会被拒绝。同一医生同一日期同一时段由数据库唯一约束防重复。

## 5. 医保失败演示

另起后端 `8081` 与前端 `5174`：

```bash
mvn spring-boot:run -Dspring-boot.run.arguments="--server.port=8081 --app.insurance.mode=FAIL"
```

在 `frontend/` 设置 `VITE_BACKEND_URL=http://127.0.0.1:8081`、`VITE_BACKEND_ORIGIN=http://127.0.0.1:5174`、`VITE_PORT=5174`、`VITE_PREVIEW_PORT=4174` 后执行 `npm run dev`。收费台实际点击医保结算后，收费单保持「待重试」，新增唯一结算失败流水，页面显示中文原因与「重新结算」，不记为收费成功。

## 6. 验收命令

先启动后端 8080、独立前端 5173、FAIL 后端 8081、FAIL 前端 5174，以及带 `--remote-debugging-port=9225` 的 Edge/Chromium CDP，再在 `frontend/` 执行：

```bash
npm run check:ui
UI_BASE=http://127.0.0.1:5174 npm run check:dynamic
npm run check:registration
npm run check:admin
npm run check:connectivity
npm run check:concurrency
npm run check:ws
npm run check:audit
npm run check:docs
npm run check:mermaid
npm run check:diagrams
npm run check:perf
```

报告输出到 `docs/images/`。`check:connectivity` 通过独立 SPA 代理实测六角色接口、患者脱敏与数据归属，不写入业务数据。`check:concurrency` 会临时创建独立患者、账号与 15 个号源，20 个并发请求抢号，验证成功恰好 15 次、号序无重复、余量归零，并在结束时清理临时数据。`check:ws` 验证患者专属主题授权、员工完整主题白名单和广播脱敏；`check:audit` 验证操作人、SYSTEM 身份、目标 ID 与业务事务释放连接后的独立审计落库；`check:docs` 验证文档、报告、图集与脚本基线一致。`check:perf` 会执行 3 轮 50 并发挂号，记录单轮与汇总 P95、吞吐、号序与余量，并在每轮结束时清理临时数据；只需 8080 后端与 MySQL，不需要浏览器/CDP。`check:mermaid` 解析 33 张设计图源；`check:diagrams` 将它们导出为 `docs/images/diagrams/` 下的 SVG/PNG，并生成 `图集索引.md` 与 `mermaid-export-report.json`，该命令不需要后端、前端或 MySQL。`UI_BASE`、`UI_CDP_PORT`、`UI_OUT_DIR`、`API_BASE`、`MYSQL_BIN` 可覆盖默认地址和路径。

## 7. 常见问题

| 现象 | 处理 |
| --- | --- |
| 页面提示「无法连接服务端」 | 确认 Spring Boot 8080 已启动；Vite 的 `/api` 代理目标是 `VITE_BACKEND_URL` 或默认 8080。 |
| 登录后立即回到登录页 | JWT 失效或服务端重启后密钥/会话不一致；重新登录即可。 |
| 挂号按钮不可用 | 检查排班是否过期、停诊、余量为 0，或当前患者账号是否缺少有效 `refId`。 |
| 角色菜单没有某个操作 | 工作台按服务端角色渲染；业务权限仍由 `@PreAuthorize` 与 JWT 复核，隐藏按钮不等于越权。 |
| 医保一直结算失败 | 当前 5174 前端连到 `app.insurance.mode=FAIL` 的 8081；换回 5173/8080 演示正常结算。 |
| 浏览器验收等待超时 | 确认 CDP 9225 可访问，且浏览器存在 `http://127.0.0.1:5173/` 或 `5174` 的页面标签。 |
| 管理维护报「完整性校验未通过」 | 检查角色编码/登录账号是否重复、患者/医生档案编号是否存在、同一医生日期时段是否重复。 |
| P95 压测报「夹具创建失败」或登录失败 | 确认 Spring Boot 8080 与 MySQL 可用，且 `admin01 / 123456`、`pt0001` 演示账号未被禁用；`check:perf` 不需要浏览器/CDP。 |
| 报告需要贴 SC/SD/ER/部署图 | 在 `docs/images/diagrams/图集索引.md` 按图号找对应 SVG/PNG；Word 优先用 PNG，放大排版用 SVG，修改语义时先改 `docs/*.md` 图源再重新执行 `npm run check:diagrams`。 |

## 8. 边界与清理

- 本系统为课程演示，使用本机 `root` 空口令与开发密钥；正式部署必须改专用数据库账号、外部密钥、HTTPS、refresh token 黑名单与迁移工具。
- 不提供患者档案 CRUD、角色/账号物理删除、智能排班、真实医保局联调、价格版本表、批次库存锁与幂等键；这些在 `docs/05-需求追溯矩阵.md` 中列为范围外或扩展设计。
- 验收脚本可能临时改写演示收费单、挂号、角色、账号或排班，但均会在 `finally` 中清理；如脚本被强杀，可重新执行 `sql/mysql/02_data.sql` 恢复干净演示基线。
- 需要贴入 Word 的图统一从 `docs/images/diagrams/` 取，图号、源文档与行号见 `图集索引.md`；`docs/*.md` 中的 Mermaid 源码仍是唯一图源，导出结果由 `npm run check:diagrams` 复验。
