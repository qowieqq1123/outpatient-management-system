## 2. 文档间依赖顺序

```text
PRD(01) ──确定需求与规则──> 概要设计(02) ──确定模块与接口──> 详细设计(03)
                                   │                              │
                                   └──────────> 数据库设计(04) <───┘
                                                  │
                       全部编号汇总 ──────────────> 追溯矩阵(05) ──> 代码与测试
                                                   │
                                                   ├──> GitHub 借鉴与选型(06)
                                                   └──> 前后端分离部署(07)
```

修改顺序必须自上而下：需求变了先改 01，再顺次检查 02/03/04 中引用到的编号，最后更新 05。反向修改（先改代码或数据库）视为破坏基线。

## 4. 图的交付形式

- 文档内图以 Mermaid 源码书写（`flowchart`、`sequenceDiagram`、`stateDiagram-v2`、`erDiagram`），保证可 diff、可复用。
- 需要贴进 Word 报告时，由 `npm run check:diagrams` 把全部 33 张 Mermaid 图导出为 PNG/SVG，放入 `docs/images/diagrams/`，并在正文保留「图源 + 导出图」双份，避免报告与源脱钩。当前 `docs/images/` 还存放浏览器验收截图与 JSON 报告；`docs/07` 的两张部署拓扑图也纳入全量导出。
- 导出命名采用稳定 ASCII 序号和图号，中文标题写入 `docs/images/diagrams/图集索引.md`；例如 `01-PRD-01-role-usecase.svg`。旧命名示例 `SC-顶层结构图.svg`、`SD-01-在线挂号.svg`、`STD-01-挂号单状态机.svg`、`ER-全局.svg` 仅供人工识别，脚本以索引为准。
- 若课程要求 draw.io / Visual Paradigm 源文件，用 Mermaid 导出的 SVG 作底图临摹，不得改图形语义。
